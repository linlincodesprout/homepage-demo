# 实现步骤与技术原理说明

> 读法建议：先看第 0 节的"小结"，其次查看第 1 节搞清楚为什么要这么干，
> 然后 A、B 两条线各按顺序读。本文所有数字均来自实际运行结果。

---

## 0. 小结总览

大模型存在一项固有局限：**它不掌握使用者本地的文件**，只记得训练时见过的内容。

要让它在自有财报上作答，只有两条路径：

| 路线 | 通俗说法 | 代价 | 对应作业 |
|---|---|---|---|
| **检索（RAG）** | 每次答题时，首先相关资料翻出来提交给它看 | 每次都要查、要带出处 | 作业 A |
| **微调（SFT/LoRA）** | 把资料"背"进模型的参数里 | 训一次要花钱，且它可能背错 | 作业 B |

课程讲义中的总纲为：**让大模型在有限的窗口里，看到信息密度最高的正确内容。**
（"窗口"= 模型一次能读进去的字数上限，读多了会忘、会乱。）

```
作业 A：  问题 → 检索（翻库找 6 块） → 拼进窗口 → 模型读着材料答 → 每句带出处
作业 B：  资料 → 造问答 → 训练 → 参数里有了"董秘的习惯" → 直接答（不查库）
```

---

## 1. 前提：模型为何无法回答私有语料的问题

大模型的工作方式极其朴素：**给定前面一段文字，猜下一个字最可能是什么**。
它没见过茅台 2026 半年报，所以问它"茅台直销收入多少"，它只能：

1. 说不知道（最好）；
2. **编一个看起来很像的数字**（最常见，也最危险）。

本项目的实测例子如下：

- 没微调、没材料 → 答"调减了 1,000.00 万元"（明显不实）
- 微调过、没材料 → 答"调减 2,419,030.09 元（来源：2022年年度报告 第72页）"（**格式完美、数字全错**）

所以整个作业的核心不是"让模型变聪明"，而是**把正确的材料，准时、准量地放到它眼前**。

## 2. 作业 A：建一个能查、能溯源的知识库

### 2.1 取语料（数据从哪来）

- 用了 **巨潮资讯网（cninfo.com.cn）**，它是证监会指定的法定信息披露平台。
- 为什么不用上交所官网？实测 `static.sse.com.cn` 会超时/反爬，而巨潮两个市场的公告都能拿到。
- 具体做法：先用 `topSearch` 接口把股票代码换成内部 `orgId`，再用 `hisAnnouncement/query`
  按"半年报"这个类别查公告列表，挑出标题里是"半年度报告"（排除"摘要/英文/更正"）的那份，
  从 `static.cninfo.com.cn` 下载 PDF。
- 结果：**12 家白酒公司 2026 半年报**（作业 A）+ **贵州茅台 2021–2025 年报**（给作业 B 当对照），
  共 18 份、1,662 页、约 1,870 万字。

### 2.2 解析 PDF：为什么要把"表格"单独拎出来

财务问题一半的答案在**表**里（利润表、分渠道收入表、现金流量表）。
如果用普通工具抽文字，表格会变成一堆没有行列关系的数字，等于废掉。

做法（用 PyMuPDF）：

1. 普通文本照抽；
2. 用 `find_tables()` 识别表格，**按行列还原**成：

   ```
   【表】按销售渠道分类的收入
   批发代理 | 38,696,577,376.60 | 5,796,572,699.06
   直销     | 52,006,683,587.88 | 3,677,189,866.82
   ```

   这样"直销 520 亿"这个数也能被检索到，而且表名不会丢。

### 2.3 切块（chunking）：为什么要切、怎么切

**为什么切**：向量模型一次只能处理 512 个 token（约 512 个汉字），模型窗口也有限。
整本报告无法一次性输入，因此需要切分为若干文本段。

**怎么切**（按课程规定的口径）：**800 字一块、相邻块重叠 120 字、尽量在句末收尾**。

- 重叠是为了防止"答案刚好被切在边界上"；
- 句末收尾是为了不把小结劈成两半；
- 每块带上**元数据**：公司名、报告名、章节、页码、类型（正文/表格）、块号。

**元数据为什么重要**：后面要回答"茅台的直销收入"，如果块上没有公司标签，
检索会把五粮液、洋河的块也检索进来来；要回答"2026 年上半年"，没有报告期标签就会
把 2022、2024 年的同类表格混进来。

结果：**11,047 块**（其中表格块约 5,700 块）。

### 2.4 向量化（embedding）：把文字变成"箭头"

这是整个 RAG 最核心的一步，用一个比喻说明：

> 把每一段文字变成一个**有方向的箭头**（数学上叫向量，我们用的是 1024 个数字组成的一支箭头）。
> 意思相近的文字，箭头方向就相近。
> 用户提问时，把问题也变成一支箭头，然后看**哪个资料的箭头和它夹角最小**，就取那几块。

几个关键点：

- "夹角小"用的是**余弦相似度**（两个箭头夹角的余弦值，越接近 1 越像）；
- 我们提前把 11,047 块全部算成箭头存成文件（`emb_qwen3.npy`，43MB），
  提问时只算问题那一支，所以检索是**毫秒级**的；
- **embedding 模型与聊天模型属于两类不同的模型**：
  `Qwen3-Embedding-0.6B`（6 亿参数，只会输出箭头，不会说话）是"尺子"，
  `deepseek-v4-flash`（会写字的）是"大脑"。尺子负责找，大脑负责答。

我们还跑了**第二条向量**（阿里 `text-embedding-v4`），就是为了对比"换一把尺子会怎样"。

### 2.5 BM25：不看意思，只看字面

向量有个短板：**字面必须出现的词它不一定能命中**（公司名、科目名、年份、条款号）。

BM25 是另一条老办法：用 jieba 把文字切成词，然后按"这个词在这块里出现几次、
在全库里稀不稀有"来打分。它擅长精确匹配，缺点是"换个说法就找不到"。

所以两条路**并排跑**：

| | 擅长 | 短板 |
|---|---|---|
| 向量 | 换词也能找到（问"自营渠道"能找到表里的"直销"） | 字面专有名词可能漏 |
| BM25 | 公司名、年份、科目名这类必须出现的词 | 口语铺垫会带偏 |

### 2.6 融合（RRF）：把两条路的排名合起来

两条路各取 30 块候选，怎么合并？用 **RRF（倒数排名融合）**：

```
某一块的分数 = 1/(60 + 它在向量路的名次) + 0.5 × 1/(60 + 它在BM25路的名次)
```

- **只比名次，不比原始分数**——因为向量的"0.83"和 BM25 的"12.7"量纲完全不同，没法相加；
- BM25 权重给 0.5，是因为它容易被"收入、渠道"这种通用词蹭到高名次；
- 最后取前 **6 块**交给大模型去读（这个 6 是课程规定的口径）。

### 2.7 生成回答：带角标的答案

把 6 块材料编号 `[1]…[6]`，连同问题发给 DeepSeek，系统提示里三条硬约束：

1. 只能依据材料回答，材料没有就写"材料未覆盖"；
2. 每句话末尾必须带 `[编号]`，点编号能回到原文；
3. 金额和比例原样引用，不许换算。

"材料未覆盖"这条特别重要——它把"编"的门堵上了。

### 2.8 评测：10 道题，逐题记录错在哪

我们出了 10 道题（8 道单公司 + 2 道跨公司全景题），每题都：

- 用 3 条路（Qwen3 向量 / 阿里向量 / BM25）分别召回，记录各自前 6 块；
- 融合后交给大模型作答；
- 和人工写的参考答案逐题比对，自动判分（关键数字命中率）。

**结果：8/10 全对，2 道全景题不对。**

而那 2 道全景题的"错"，恰恰是课程讲义早已指出的现象。

## 3. 作业 A 里三个真正值钱的发现

### 3.1 第一版把课程讲义原题答错了，查出三个原因

题目：贵州茅台 2026 上半年直销收入是多少、占营业收入多少？

第一版答的是"材料未覆盖"——**错的**。查下来：

1. 检索时 BM25 把"洋河股份""水井坊"的块混了进来（它们也含"渠道/收入"）；
2. 问"2026 年上半年"，但 2022、2024、2025 年的同类表格也挤进了前 6；
3. 融合规则让"两条路都出现但都很靠后"的块，压过了"只在向量路靠前"的正确块。

三处一起改（**公司名硬过滤 + 报告期硬过滤 + 剔除 BM25 零分候选 + 向量权重 2:1**）后转正。

> 原理：这跟课程讲义"法规库要剔除废止版本"是同一件事——
> **向量只懂"像不像"，不懂"哪个才是现行/本期"**，时效和归属必须靠元数据字段管。

### 3.2 碎片拼不出全景（这是向量 RAG 的先天缺陷）

全景题问"12 家里谁的营收增速最高"，答题窗口只有 6 块，
装得下 1-2 家公司，剩下的根本没进窗口。我们做了对照实验：

| 做法 | 输入的块 | 覆盖到几家公司 |
|---|---|---|
| 一次检索 top6（基线） | 6 | 2 / 12 |
| 把 k 加到 60 | 60 | 3 / 12 |
| 12 家公司各检索一次 | 24 | 3 / 12 |
| **离线抽一张跨公司指标表** | 6 + 一张表 | **12 / 12** |

> 原理：**加宽窗口无法解决全景题，把结构化事实离线预处理好才行**。
> 这就是课程讲义中"知识侧装一层"的账：预处理一次，以后每次都能用。

### 3.3 上下文不是越多越好（我们刚遇到）

我为了解决"材料里有答案却答错"，把 top-6 放宽到 top-12，结果：

| 版本 | 正确率 |
|---|---|
| top-6 | **37%** |
| top-12 + 口径标注 + 更长的提示词 | **12%**（更差） |

> 原理：材料从约 4,800 字涨到约 10,000 字，干扰表更多，2B 小模型的注意力被摊薄。
> 这正是课程讲义中的表述："**窗口是工作台不是仓库**——工作台上只放这一轮要用的内容。"

## 4. 作业 B：把"董秘"训进一个小模型

### 4.1 造训练数据（为什么不能直接拿财报去训）

课程讲义原文：**"直接塞上下文 = 什么都没学"**。
要让它学会"遇到这种问法就这样答"，必须先有**问答题对**。

做法：让大模型读一段财报原文，生成一组"投资者问 / 董秘答"，硬性要求：

- 问题要像真实投资者问的（不许出现"第 X 页""表格中"这种元信息）；
- 答案只准用原文信息，数字一模一样；
- 答案末尾必须是"（来源：报告全名 第 X 页）"。

结果：生成 660 组，其中 73 块原文太碎（表被切得只剩数字）主动跳过。

### 4.2 抽检（本作业要求"人工抽检删掉编造的"）

两层：

1. **机器**：把答案里的每个数字回到原文里核对；对不上、缺出处、页码不符就打标；
2. **人工**：随机抽 40 条导成表格，逐条看问题和答案是否属实。

成果：440 条里 3 条有问题，删掉 → **404 条干净样本**（364 训练 / 40 验证）。

### 4.3 结构化文本：输入的到底是什么

不是把问题和答案简单地放在一起，而是用 Qwen 的**对话模板**拼成一段结构化文本：

```
<|im_start|>system
你是贵州茅台酒股份有限公司的董事会秘书……回答末尾标注（来源：报告全名 第 X 页）……<|im_end|>
<|im_start|>user
2022年上半年末，公司递延所得税资产较上年期末变动明显，具体金额和占比是多少？<|im_end|>
<|im_start|>assistant
2022年上半年末，公司递延所得税资产为3,134,613,141.01，占总资产比例1.31%……
（来源：贵州茅台2022年半年度报告 第8页）<|im_end|>
```

那些 `<|im_start|>` 就是"符号"，模型看到这些符号就知道：该轮到我用 assistant 的身份说话了。
训练就是把"看到 system+user，就续写 assistant 那一段"变成习惯。

### 4.4 LoRA / QLoRA：为什么小显卡也能微调 27 亿参数的模型

**微调**的本意：把模型里几十亿个参数，按"答错了就往下调一点"的方向挪一挪。
全参数训一遍，显存根本不够。

**LoRA 的巧劲**：

> 把原来的大矩阵**冻住不动**，在旁边并联两个很小的矩阵（r=16 的瓶颈），
> 训练时只更新这两个小矩阵，最后把它们"加"回原模型。
> 相当于不改教科书，只贴一张便签。

**QLoRA** 再加一招：把冻住的原模型压成 **4bit** 存（显存再省一半多），
计算时临时升精度，梯度照样能穿过去。

我们这次的数字：**可训练参数 10,911,744 / 总参数 1,374,217,024 ≈ 0.79%**。
（这个 10,911,744 和课程讲义录屏里的数字一模一样，说明 LoRA 配置和课程是同一套：r=16，
作用在 q/k/v/o/gate/up/down 七个投影层上。）

### 4.5 训练过程在干什么

每一步就三件事：

1. 把一条问答输入，让模型**逐字预测**答案那一句；
2. 预测错了就算"误差"（交叉熵损失），误差反向传回去，轻轻推动那两个小矩阵；
3. 重复。训练完 loss 从 3 点多降到 0.71（6 轮版本）。

结果：3 轮 5.8 分钟、6 轮 11.0 分钟（RTX 4080S 32G），LoRA 权重只有 20.8MB。

### 4.6 四格对照：为什么评测要这么设计

只看"训完答得对不对"区分不出两件事：

- **背下来了**（训练过的事实，换种问法也能答）
- **会举一反三**（从没训练过的事实，也能答）

所以用 2×2 四个格子：

| | 原问法 | 换问法 |
|---|---|---|
| **训练过的事实** | 背住了没 | 背的是意思还是字面 |
| **从未训练的事实** | 会用没 | 真有本事没 |

再加两格"知识库 + 同一个小模型"，就能回答课程规定的核心问题：
**同一批财报，到底该建库还是该微调？**

## 5. 作业 B 的结果怎么读（以及为什么低）

四格结果（160 条冻结题库）：

| 配置 | 训练过·原问法 | 训练过·换问法 | 从未训练·原问法 | 从未训练·换问法 |
|---|---|---|---|---|
| 没微调 | 5% | 5% | 0% | 0% |
| 微调过 | 5% | 5% | 0% | 0% |
| 知识库 + 没微调 | 20% | 13% | 20% | 30% |
| 知识库 + 微调过 | **37%** | 25% | 30% | 35% |

三条结论：

1. **微调学会了格式与口吻**：带出处率从 44/60 涨到 60/60，但"完全答对"始终 5%。
   更要警惕的是**编造变得更像真的**（格式全对、数字全错）。
2. **事实靠知识库递进来**：同一题没材料 8% 命中、给材料 43%。
3. **微调的价值是"更会用材料"**：同样有知识库在前，完全答对 20% → 37%。

### 那 37% 为什么还不够高？拆开看

| 失分原因 | 占比 | 说明 |
|---|---|---|
| **检索没取到** | 上限 69% | 160 条里只有 110 条的"答案块"进了 top-6 |
| **口径取错（最大头）** | 110 条里只答对 44 条 | 材料同时给了"合并报表"和"母公司报表"，科目名一字不差，模型取错那张 |
| **判分偏严** | 少量 | 差一个数字（如 17.63% 写成 17.62%）也判全错 |

典型例子：问"2022 年销售商品收到的现金"，参考是**合并口径 1,406.9 亿**，
模型答成**母公司口径 606.3 亿**——这正是课程讲义指出的"**口径陷阱**"。

## 6. 术语速查表

| 术语 | 小结解释 |
|---|---|
| token | 模型眼里的"字"，中文大约 1 字 ≈ 1 token |
| 窗口 | 模型一次最多能读进去的 token 数，读满就"记不住前面" |
| embedding / 向量 | 把文字变成一串数字（一支箭头），方向代表意思 |
| 余弦相似度 | 两支箭头夹角的余弦值，越接近 1 越像 |
| RAG | 先检索、再把材料提交给模型回答 |
| 切块 / chunk | 把长文档切成模型能处理的小段 |
| BM25 | 按词频统计的经典全文检索算法 |
| RRF | 把多条检索路的名次融合成一个排序 |
| 硬过滤 | 用元数据（公司、年份）直接排除不符合的块 |
| SFT | 监督微调：喂"问题→标准答案"，让它学会这样答 |
| LoRA | 冻结原模型，只训练旁边两个小矩阵 |
| QLoRA | LoRA + 把原模型压成 4bit，省显存 |
| 交叉熵损失 | 衡量"预测的下一个字"和"正确答案"差多少 |
| 口径 | 合并报表还是母公司报表（数字会不一样） |
| 全景题 | 需要横跨多家公司的聚合问题 |

**小结记住整件事**：
知识库负责"事实对不对"，微调负责"答得像不像、会不会用材料"。
只做前者，答案对但不像人；只做后者，像人但全是编的。
